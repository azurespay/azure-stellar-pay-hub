# OpenSSF Best Practices badge — self-assessment

**Status: prepared, not yet registered.** Nothing in this repository claims the
badge. Registering is a manual step that needs a maintainer's GitHub login at
[bestpractices.dev](https://www.bestpractices.dev/) (the site authenticates with
GitHub OAuth, so it cannot be done from CI or by an automation token), and no
badge may be shown in the README until the BadgeApp reports the level as
achieved.

This file is the substance of that registration: every criterion of the
**passing** level ([authoritative list](https://www.bestpractices.dev/en/criteria/0),
retrieved 2026-09-15) mapped to the artefact in this repository that satisfies
it, or to the honest reason it does not yet. Its purpose is that the
questionnaire can be filled in and re-checked by a reviewer instead of being
trusted.

## Registering (about ten minutes)

1. Sign in to <https://www.bestpractices.dev/> with GitHub.
2. **Add New Project**, then paste:
   - **Name:** Azure StellarPay Hub
   - **Repository URL:** `https://github.com/azurespay/azure-stellar-pay-hub`
   - **Home page URL:** the repository README, or the hosted frontends listed in
     the README
   - **License:** `MIT` (SPDX identifier)
3. Answer the criteria using the table below, copying the justification text
   where the status is not a plain "Met" — the BadgeApp asks for a URL or a
   short justification per criterion, and the "Evidence / justification" column
   is written to be pasted in.
4. Four criteria are **human attestations** and can only be answered by a
   maintainer: `know_secure_design`, `know_common_errors`, `report_responses`
   and `vulnerability_report_response`. Do not answer them on the project's
   behalf.
5. Once the badge is awarded, replace the README badge (see
   [After the badge is awarded](#after-the-badge-is-awarded)).

## Criteria (passing level)

Status legend: **Met** · **Met (URL)** — a URL is required in the form ·
**Partial** — the criterion is met for what exists, with a named gap ·
**Attest** — answerable only by a maintainer · **N/A** — not applicable, with
the required justification · **Not met** — a suggested criterion the project
does not satisfy.

Nothing in the **MUST** column is unmet except `version_unique`, which is a
consequence of nothing having been released yet rather than of anything being
wrong with the repository. The three gaps a maintainer can close without
changing code are: cut the first tagged release, answer the four attestation
criteria, and (optionally) wire up a fuzzing or DAST target.

## After the badge is awarded

Replace the README badge with the official one, substituting your project id
(`<id>` is visible in the URL of the project page, e.g.
`https://www.bestpractices.dev/projects/<id>`):

```markdown
[![OpenSSF Best Practices](https://www.bestpractices.dev/projects/<id>/badge)](https://www.bestpractices.dev/projects/<id>)
```

Then update the `CII-Best-Practices` row of the OpenSSF Scorecard section in
[`SECURITY.md`](../SECURITY.md) — that row currently explains why the check
scores zero, and the Scorecard will pick up the badge on its next run.
